# تطبيق BSC KU — دليل التشغيل

تطبيق أندرويد و iOS مبني على Capacitor، يلفّ نفس صفحات موقع
[biosci-ku.com](https://biosci-ku.com) ونفس مشروع Firebase — فأي محتوى تنشره
من لوحة الإدارة يوصل الموقع والتطبيق بنفس اللحظة، بدون تحديث للتطبيق.

---

## الأوامر

```bash
npm run apk         # يبني كل شي ويطلع ملف APK جاهز للتثبيت
npm run build:app   # يبني www/ وينقلها للأندرويد و iOS
npm run sync        # يبني www/ فقط من صفحات الموقع
npm run assets      # يعيد توليد الأيقونات وشاشات البداية من الشعار
npm run dev         # سيرفر تجربة الموقع (localhost:5173)
npm run dev:app     # معاينة شكل التطبيق بالمتصفح (localhost:5174)
```

---

## بناء نسخة أندرويد

```bash
npm run apk
```

الناتج: `android/app/build/outputs/apk/debug/app-debug.apk` — انقله للجوال
وثبّته (فعّل "تثبيت من مصادر غير معروفة").

للنشر على Google Play: `node .claude/build-apk.js release` — وتحتاج مفتاح
توقيع تضيفه في `android/app/build.gradle`.

### ملاحظة عن مسار المشروع

مسار المشروع فيه أحرف عربية ("الملفات المهمة")، وهذا يكسر بناء أندرويد
من سطر الأوامر: `gradlew.bat` يمرّر المسار بترميز النظام فتتحول الأحرف
العربية لعلامات استفهام وما يلقى Java ملفاته.

سكربت `npm run apk` يتجاوزها تلقائياً — يسوي اختصار مجلد (junction) بمسار
إنجليزي `C:\bsc-ku-build` يشير لنفس المشروع ويبني منه. ما تحتاج تسوي شي.

**لو نقلت المشروع لمسار إنجليزي بالكامل** (مثل `C:\bsc-ku`) تختفي الحاجة
للاختصار ويصير كل شي أبسط — وهذا الأفضل على المدى الطويل.

## بناء نسخة الآيفون

مشروع iOS جاهز بالكامل في `ios/`، **لكن بناءه يحتاج جهاز Mac** فيه Xcode —
هذا قيد من أبل مو من المشروع. على الماك:

```bash
npm run build:app
npx cap open ios
```

ثم من Xcode: اختر جهازك و Run. للنشر على App Store تحتاج حساب مطوّر أبل
(٩٩ دولار سنوياً).

## الإشعارات (تحتاج خطوة منك)

الكود جاهز بالكامل في `app-shell/native.js`: يطلب الإذن، يسجّل رمز الجهاز في
مجموعة `deviceTokens` بـ Firestore، يعرض الإشعار داخل التطبيق لو وصل والتطبيق
مفتوح، ويفتح الصفحة المقصودة عند الضغط عليه.

الناقص ملف واحد:

1. افتح [Firebase Console](https://console.firebase.google.com) → مشروع `bsc-ku`
2. Project settings → Your apps → Add app → Android
3. Package name: `com.bscku.app`
4. نزّل `google-services.json` وحطه في `android/app/google-services.json`
5. `npm run build:app` ثم أعد البناء

Gradle يكتشف الملف تلقائياً ويفعّل الإشعارات. بدونه التطبيق يشتغل عادي،
بس بدون إشعارات push.

**ولا تنسَ**: انشر `firestore.rules` المحدّثة من Firebase Console — فيها قاعدة
`deviceTokens` الجديدة، وبدونها تسجيل الأجهزة يفشل.

لـ iOS تحتاج زيادة شهادة APNs من حساب مطوّر أبل.

### إرسال إشعار

من Firebase Console → Messaging → New campaign. لتوجيه المستخدم لصفحة معيّنة،
ضِف في بيانات الإشعار مفتاح `page` بقيمة اسم الصفحة (مثل `events.html`).

## بنية المشروع

```
الجذر/           صفحات الموقع — تعديلها ينعكس على الموقع والتطبيق
app-shell/       واجهة التطبيق فقط (شريط سفلي، هيدر، جسر النظام)
  app-nav.js       التنقل، قائمة المزيد، السحب للتحديث، شريط الاتصال
  native.js        شريط الحالة، زر الرجوع، الاهتزاز، الإشعارات، المشاركة
  app.css          تخطيط الجوال
www/             مولّد بالكامل — لا تعدّل فيه (ينمسح كل بناء)
assets/          مصادر الأيقونة وشاشة البداية
android/  ios/   المشروعان الأصليان
```

قاعدة وحدة تحكم كل شي: **عدّل على صفحات الموقع أو على `app-shell/`، وشغّل
`npm run build:app`.** لا تعدّل داخل `www/` أبداً.

لإضافة صفحة للتطبيق: ضِف اسمها في `PAGES` داخل `.claude/sync-app.js`، وضِف
رابطها في `SHEET` داخل `app-shell/app-nav.js`.

`admin.html` مستثناة عمداً — لوحة الإدارة تبقى على الويب.
